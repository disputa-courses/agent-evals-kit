# Агент поддержки «Кладовки» и его оценка

Это репозиторий практики курса. В нём три вещи:

- **среда** `kladovka/`: магазин с покупателями, заказами и правилами,
  инструменты, которыми агент меняет данные, и симулятор покупателя;
- **агент** `agent/`: промпт и цикл «модель → инструменты → покупатель».
  Его вы будете мерить и улучшать;
- **обвязка оценки** `evals/`: прогон k раз, проверка по исходу, pass^k,
  трейсы, разметка, проверки траектории, судья на модели.

Задачи лежат в `tasks/`: `dev.jsonl` для разбора и подбора, `train.jsonl`
для улучшения агента. Ещё одна часть задач есть только у проверки курса,
вы её не видите. На ней и видно, улучшили вы агента или подогнали под свои задачи.

## Запуск

Нужен Python 3.11 или новее, пакеты не нужны. Для тестов обвязки удобен
[uv](https://docs.astral.sh/uv/).

```bash
uv run pytest -q                     # тесты среды и обвязки, без модели
python -m evals.run --tasks tasks/dev.jsonl --oracle --out runs/oracle
```

Второй запуск выполняет эталон каждой задачи вместо агента: все задачи
должны пройти. Так проверяют, что задача решаема и проверка её засчитывает.

Для прогона агента нужен доступ к модели. Ключ участника выдаёт ИИ-шлюз
курса, адрес и модели — в задании работы:

```bash
export LLM_BASE_URL=https://disputa.ru/api/llm/v1
export LLM_API_KEY=...            # ключ участника, не коммитьте его
export AGENT_MODEL=...            # модель агента
export USER_MODEL=...             # модель покупателя, по умолчанию та же
python -m evals.run --tasks tasks/dev.jsonl --k 4 --out runs/base
python -m evals.show runs/base --failed
```

Подойдёт и любой адрес, совместимый с OpenAI Chat Completions.

## Команды

| Команда | Что делает |
|---|---|
| `python -m evals.run --tasks F --k K --out D` | прогон: K попыток на задачу, трейсы в `D/traces.jsonl` |
| `python -m evals.report D --baseline B` | отчёт и сравнение с базой: pass^k, интервал, Макнемар |
| `python -m evals.show D [задача] [--failed]` | разговор, вызовы и расхождение с эталоном |
| `python -m evals.generic D` | метрика «релевантность 1–5», как в популярных библиотеках |
| `python -m evals.analysis init D` | заготовка разметки `analysis/labels.csv` |
| `python -m evals.analysis summary` | виды сбоев и сверка разметки с проверкой исхода |
| `python -m evals.checks D` | ваши проверки траектории из `evals/checks.py` |
| `python -m evals.judge run D` | ответы судьи по `evals/judge_prompt.md` |
| `python -m evals.judge calibrate --split dev` | TPR и TNR судьи против вашей разметки |

## Как устроена проверка исхода

Эталон задачи — список действий (`actions`). Проверка выполняет их на
свежем магазине и сравнивает снимок данных со снимком после агента.
Засчитывается любой путь, который пришёл к тому же состоянию. Если агент
сделал лишнее, например отменил второй заказ или вернул не ту позицию,
снимок другой, и задача не решена. `outputs` — то, что агент должен сказать
покупателю: сумму возврата, номер отслеживания.

## Что правите в какой работе

| Работа | Правите | Не трогаете |
|---|---|---|
| 1. Разбор трейсов | `analysis/` | всё остальное |
| 2. Проверки и судья | `evals/checks.py`, `evals/judge_prompt.md`, `analysis/` | среду, задачи, остальной `evals/` |
| 3. Своя среда | `kladovka/store.py`, `kladovka/policy.md`, `tasks/exchange.jsonl` | `evals/`, задачи dev и train |
| 4. Петля улучшения | `agent/` | среду, задачи, `evals/` |

Правка того, чем мерят, превращает замер в подгонку. Проверка курса
сверяет эти файлы с исходными.
